# 栖居 · HABITAT

一个可以环绕探索、逐个控制灯光与家电的 3D 家庭前端项目。以温暖木色、低饱和绿色和清晰的空间层次组织交互。

在线预览：<https://fanhuayishiy.github.io/ai-demo/habitat-interactive-home/dist/>

| 依赖 | 版本 | 用途 |
| --- | --- | --- |
| React | 19 | 页面状态、设备面板与响应式交互 |
| Three.js | 0.180 | 程序化家庭模型、灯光、相机和射线拾取 |
| TypeScript | 5.8 | 严格类型检查 |
| Vite | 6 | 开发服务器和生产构建 |

## 主生成提示（原文）

> 我希望写一个网页，是一个一个3d家庭模型，模型里类似 酷家乐  那种3维视图，展示主要软硬装家具家电，能够旋转拖动（自动隐藏遮挡视野的墙体）。其中的灯光家电是可以交互的，也就是点击开关灯，或者能够弹出交互菜单出来。
> 你开发一个独立的前端（根据情况也可以一并开发后端服务）项目，这里有户型图以及实拍图。 户型图和实拍图建立3维模型，要做到让每个电器实体都可以点击交互反馈有菜单，核心你要做可交互的家庭3d模型，我可以拖动旋转放大，点击户型里的具体某个电器，开关灯也会影响环境光线，注意一个房间可能有多个灯。
> 你要有高标准的审美，不能像酷家乐那样简约丑陋，优雅的交互效果
>

### 同一条提示的拆解版（整理后逐条执行）

请开发一个独立的、高完成度前端项目，呈现一个可以自由探索的 3D 家庭空间。整体体验参考专业家装软件的三维视图，但视觉质量、材质表现和交互细节要更有审美，避免模板化、廉价或简陋的家装界面。

### 空间与建模

- 以用户提供的户型图和室内实拍图为建模依据，建立可环绕观察的完整家庭 3D 模型。
- 按真实户型还原房间关系、墙体、门窗、地面、吊顶、柜体和主要软硬装；家具、灯具、家电的位置、比例和朝向应与资料保持一致。
- 展示客厅、卧室、书房、餐厨、卫浴、阳台等主要空间，以及沙发、床、餐桌、橱柜、电视、冰箱、洗衣机、空调、卫浴和装饰物。
- 当前没有真实户型图和实拍图时，使用明确标注的原创示例户型，不得把示例空间描述成真实房屋还原；收到资料后再替换为实景模型。

### 三维操作

- 支持鼠标拖动旋转、滚轮缩放、右键或双指平移；移动端支持单指旋转和双指缩放。
- 支持全屋总览、房间聚焦、俯视平面和视角复位。
- 根据观察方向自动淡出或隐藏遮挡视野的墙体，墙体切换要平滑；同时提供完整墙体和隐藏墙体模式。
- 设备、灯具和家具都应保持稳定的实体位置、尺寸和点击区域，不能因为标签或悬浮效果改变布局。

### 设备交互与灯光

- 每一个电器和灯具都是独立可点击实体。点击实体后，在侧边栏或浮层打开对应控制菜单，并显示设备名称、所属房间、当前状态和可用控制项。
- 灯具至少支持独立开关、亮度和色温；一个房间有多盏灯时，每盏灯必须可以分别控制，不能共用一个房间开关。
- 灯光开关、亮度和色温要实时影响 3D 场景中的点光源、发光材质和房间环境光；日光、暮色、夜晚应有明显但自然的光影差异。
- 家电根据类型提供合理交互，例如电视画面模式、空调模式和温度、窗帘开合、冰箱温度、烤箱温度、洗衣程序、音箱内容和扫地机器人运行状态。
- 提供归家、观影、睡眠、离家等场景预设；状态可保存在当前浏览器，清晰注明这是本地模拟，不代表真实家电控制。

### 视觉与交付标准

- 使用有层次的建筑材质、木材、织物、石材、玻璃和金属表现，采用克制的暖白、木色、低饱和绿色和夜间暖光配色。
- 控件、标签、面板和动画服务于空间理解，保持简洁、安静、优雅；避免过度玻璃拟态、装饰性渐变、拥挤卡片和酷家乐式默认模板感。
- 为按钮、滑杆、弹窗、状态变化和设备选中提供清晰反馈，支持键盘焦点、触摸操作、减少动态效果偏好和 WebGL 不可用时的说明。
- 前端优先采用静态可部署架构；只有在需要接入真实设备、账户或远程状态同步时，才增加后端服务，并明确设备协议、鉴权和数据边界。

## 运行

建议使用 Node.js 22.6 或更新版本。首次运行：

```bash
npm install
npm run dev
```

打开终端显示的本地地址（通常是 `http://localhost:5173`）。

```bash
npm run build    # TypeScript 检查与生产构建，产物位于 dist/
npm run preview  # 本地预览生产构建
npm test         # 设备状态、场景与持久化测试
```

项目不依赖后端、账户、外部 3D 模型下载或 API 密钥；`dist/` 是已提交的 GitHub Pages 预览产物。

## 使用方法

- 在三维空间按住鼠标左键拖动旋转，使用滚轮缩放；鼠标右键拖动平移。触屏可单指旋转、双指缩放和平移。
- 点击房间导航聚焦对应空间；使用视图控制切换全屋视角和俯视图，也可以「保存空间快照」导出当前画面 PNG。
- 自动墙体模式根据观察方向隐藏遮挡视线的墙面，也可切换显示或隐藏墙体。
- 点击三维模型中的灯具或家电，打开对应的设备控制菜单；也可从设备列表选择。
- 每个灯具有自己的开关、亮度和色温。客厅、主卧、书房和餐厨均包含多路独立灯光，操作会直接影响三维空间的照明。
- 电视、空调、窗帘、冰箱、抽油烟机、烤箱、热水器、洗烘机、扫地机器人和音箱都有独立设备状态；可用控制项取决于设备类型。
- 回家、观影、睡眠和离家四个场景预设（界面文案为舒适归家、沉浸观影、一夜好眠、安心离家）会批量调整设备；冰箱在这些场景中保持运行。
- 设备设置会保存在当前浏览器的本地存储中，刷新后恢复；日间、黄昏和夜间环境用于观察不同照明效果。

## 户型与素材说明

用户未提供户型图与实拍照片，因此本项目采用**原创 108㎡ 示例户型**，没有将示例包装为真实房屋的照片重建。参考平面图位于 [`public/floorplan.svg`](public/floorplan.svg)，开发服务运行后可直接访问 `/floorplan.svg`。

外轮廓为 12 m × 9 m。三维坐标约定：X 为东西方向，Y 为高度，Z 为南北方向；模型平面范围 X ∈ [-6, 6]、Z ∈ [-4.5, 4.5]。

| 分区 | X 范围（m） | Z 范围（m）  | 示意尺寸    |
| ---- | ----------- | ------------ | ----------- |
| 主卧 | -6 至 -2    | -4.5 至 0.6  | 4.0 × 5.1 m |
| 卫浴 | -6 至 -2    | 0.6 至 4.5   | 4.0 × 3.9 m |
| 书房 | -2 至 2.3   | -4.5 至 -0.8 | 4.3 × 3.7 m |
| 客厅 | -2 至 2.3   | -0.8 至 4.5  | 4.3 × 5.3 m |
| 餐厨 | 2.3 至 6    | -4.5 至 2.5  | 3.7 × 7.0 m |
| 阳台 | 2.3 至 6    | 2.5 至 4.5   | 3.7 × 2.0 m |

墙体、门窗、软装、家具和电器使用程序化几何体及材质搭建；户型图是与示例空间分区对应的设计示意，不用于施工。后续收到真实尺寸与照片后，可在此基础上替换空间配置和家具模型。

## 项目组织

- `src/types.ts`：房间、设备、场景及三维组件接口。
- `src/data.ts`：房间与设备清单、场景状态转换、持久化状态读取及数据校验。
- `src/main.tsx`：React 应用入口。
- `src/App.tsx`：设备面板、房间导航、场景预设、弹窗与交互状态。
- `src/scene/HomeScene.tsx`：Three.js 渲染、射线拾取、相机控制与墙体可见性。
- `src/scene/house.ts`：户型、家具与家电程序化模型。
- `src/styles.css`：视觉样式、布局和响应式界面。
- `public/floorplan.svg`：可独立查看的示例户型图。
- `tests/home-state.test.ts`：设备数据和状态行为测试，使用 Node.js 内置测试器，无额外测试依赖。

三维物体与设备状态通过稳定的设备 ID 关联，React 管理交互状态，Three.js 更新对应实体和灯光。场景由程序化几何体构建家具、软装、墙体、门窗与 22 件可交互设备。每个灯具都是独立设备，而不是整间房共用一个灯光开关。

## 功能边界

这是可独立运行的空间交互演示。设备控制、运行模式及功率数字均为**本地模拟**，不会连接或操作真实家电；功率是演示用额定参数，不代表真实电表读数。接入真实家庭设备时，应由独立后端处理身份认证、设备协议和状态同步，再将设备状态映射到现有设备 ID。

画面需要支持 WebGL 的现代浏览器；复杂三维渲染的流畅度受显卡、浏览器和设备性能影响。
