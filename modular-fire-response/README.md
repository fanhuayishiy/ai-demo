# FIRELINK 分布式智能消防

面向消防专业交流与公众科普的实时 3D 概念演示。夜间微缩街区中，多个站点按预案派出模块化车组，移动增压车组织供水，承托无人机依次提起同一根水带，地面设备和人工指挥共同推进任务。

[在线预览](https://fanhuayishiy.github.io/ai-demo/modular-fire-response/dist/) · [完整复现提示](./docs/RECREATE_PROMPT.zh-CN.md) · [发布验证记录](./docs/VALIDATION.md)

**这不是实战指挥系统、真实设备控制系统或经过工程验证的消防仿真。建筑、人物、时序、资源和设备参数都是演示设定。**

## 主生成提示（原文）

以下逐字保留本次项目中可核验的初始用户请求，不把后续实现规格冒充历史提示。

```text
我现在想做一个分布式模块化的智能消防系统，你跟我讨论一下可行性，最终生成一个游戏化 3D消防系统展示的模块。我的想法是：把消防改成模块化小型化想现在的无人驾驶车辆和无人货运车辆一样，弄成多模块如：供水车（供水加压、自动前往加水点加水、水管并网）、**举高喷射消防车**（臂架和水炮）、电池供能车、机械狗车（提供机械狗装备）、工具车（提供破拆工具等）、消防无人机机场车（提供多个无人机空中喷水）、侦查无人机车（提供侦查无人机检测建筑生命活动、无人机空中侦查）、载重无人机车（载重无人机吊人和投送救生设备），云梯车（比较大，提供云梯救援），在不同地区分布式存放这些消防设施，当火灾发生先让侦查无人机飞到指定地点侦查和引导救援、更加火势调度附近的多模块车辆自动前往，到地方自动/手动组装，小型车辆方便进入狭小的位置，分布式方便根据火势调度，机械狗车到达通过多个机械狗连接水管分摊重量直接冲入火场救火，供水车连接需要供水的车辆进行供水，并且在没水的时候自动前往附近加水区域自动供水，或者直接连接普通水网进行补水，机械狗还能带上一些设备消防斧等，消防无人机机场车也是通过多个无人机分摊水管重量，根据高度起飞不同的无人机，对高空火灾进行救火，载重无人机可以带一些消防设备如防毒面罩、救生梯等投送给被困人员，极端情况下也可以充当空中吊车，这中间重点展示分布式、自动补水、提前侦查、生命检测、自动调配、高空无人机灭火、无人机投送物资和吊人、机械狗冲入火场、人机协同等
```

## 功能亮点

- 三个分布式站点、两个设定水源点、十二辆车、十类模块；侦查与地面首批响应并行，疑似生命线索触发后续增援。
- 三辆供水车独立往返补水；M01 移动增压车抵达作业位并获连接授权后供水。撤回增压车立即停止下游供水，缓冲储水仍受有限容量约束。
- F01 两架白色托举机和一架红色末端喷射机，共同连接一根从载车卷盘放出的水带。前两架不带独立水炮，负责下段和中段承托；最后一架才负责喷射。
- 三机每隔 7 秒起飞，各自 4 秒的垂直起飞阶段不重叠；承托机于出动第 16、23 秒就位，末端于第 30 秒就位，有供水时按单喷头 6 L/s 的虚构需求演示。待起飞机始终连管，返航时连续收回。
- C01 重载无人机从车上起飞、航渡并吊放四组物资；交接后才计入交付。正常流程历时 64 秒演示时间，第 34 秒完成交接；中断任务先回收飞行器，再移动车辆。
- 机器犬沿入口队列搜索与携管，举高喷射车和云梯各有独立作业动作；热信号为疑似线索，需人工复核。人员转移计入云梯救援，概念吊篮只承载模拟载荷。
- 引导演示与人工指挥共用状态；支持选择、搜索、聚焦、跟随、镜头巡览、暂停、倍率、重置，以及道路、供水、无人机和能源故障开关。
- 夜间冷白作业灯、暖窗光、消防红与青色水带分层显示；桌面指挥栏、紧凑装备带和手机折叠面板保留场景空间。主画面是可操作的 Three.js 场景，不是背景截图。

## 运行方式

使用 Node.js 22.12 或更新的 22.x 版本，以及支持 WebGL / 硬件加速的现代浏览器。

```sh
cd modular-fire-response
npm ci
npm run dev -- --port 5183
```

以终端实际输出的地址为准；不要直接双击开发入口 `index.html`。首次安装依赖需要网络，模型、字体回退、纹理生成及装备图片不依赖在线模型或 CDN。

```sh
npm test
npm run build
npm run preview -- --port 5184
```

`dist/` 是新构建并提交的静态预览，使用相对 Vite base，装备缩略图同样遵循 `BASE_URL`。合集首页将本项目列在最后；推送后由仓库现有 GitHub Pages 工作流打包，统一源码入口只在发布副本中注入。

演示最多推进 180 秒模拟时间，任务结束后留在复盘，不自动循环。后台页面不推进时钟；系统偏好减少动态效果时默认暂停。引导模式的授权以指挥事件呈现，不代表 AI 自行取得实际执行权限。

React 19、TypeScript、Vite、Three.js、React Three Fiber、Drei、Lucide、ngraph.graph / ngraph.path；Vitest 和 Testing Library 用于逻辑、组件与几何回归。

```text
src/
  App.tsx              共享状态、播放时钟、图形容错
  simulation/          调度预案、道路交通、水量、授权、航空时序
  spatial/             建筑、道路、泊位及作业目标的统一空间布局
  scene/               模型、夜景、管线、特效、镜头与标签
  ui/                  指挥栏、搜索、装备选择和人工干预

docs/                  复现规格与发布验证
dist/                  可直接静态托管的生产构建
```

## 验证与边界

自动测试覆盖任务授权、水量收支、补水轮换、交通与转向、三机顺序起飞、真实挂点连续接管、渲染半径间隙、单喷头供水、物资交接、故障回收、界面状态与子目录资源路径。发布时的实际命令和结果见 [验证记录](./docs/VALIDATION.md)。

最终版本的浏览器视觉验收仍受工具安全策略限制，未取得本次最终桌面、手机或窄屏截图。静态构建和测试通过不等于已验证最终 WebGL 画面、GPU 状态、帧率或所有视角。

- 调度是预设规则和道路图搜索，不是最优 AI 调度、真实无人驾驶或现场指挥建议。
- 供水仅为简化收支，未求解泵曲线、水压、水锤、消防水力瞬态或火灾 CFD；市政补水可用性是场景假设。
- 机器犬携管和无人机承托是动画概念，轻微水带下垂不是张力、载荷、喷射反力或多体动力学结果。采样间隙检查不能代替连续碰撞检测、工程试验或安全认证。
- 生命信号没有连接真实传感器，不具备隔墙透视或自动确认人员的能力。
- 吊运默认关闭，需独立概念开关、线索复核和卸货后悬停窗口内的明确授权；只展示模拟载荷，不计为人员获救，也不构成实际执行许可。
- 不接入真实 GIS、硬件、无人机、管网、指挥平台或后端。
