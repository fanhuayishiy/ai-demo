# Roadster 逃离收费站

2026 年 10 月 16 日特斯拉第二代 Roadster 发布（搭载 SpaceX 冷气推进器 A71，可空中悬浮与翻滚），网友玩梗「开特斯拉的人谁还过收费站，直接飞过去」。本 Demo 据此做成一个单文件结构的 Three.js 网页小游戏：长按点火，在收费站前起飞飞越，点火太晚会撞上收费站，推力过猛会飞过头冲出马路。

## 一键复现提示词

上面是当时逐条提出的原始请求，可核验但全是「要求」——没有方法、没有验收标准。所以车尾返工了三轮才定对比例，验证工具也是做到后面才补的。

下面是按本次经验改写后的版本：**把形容词换成动作和数字，把验证工具写成交付物**，用它重做这个 demo 可以大幅减少来回。

```text
网上找资料，帮我做一个 Roadster 逃离收费站 网页小游戏，用 three.js：
玩梗 2026 年特斯拉第二代 Roadster 的 SpaceX 冷气推进器——开特斯拉的人谁还过收费站，
直接飞过去。长按点火，车底推进器向下喷气把车顶起来飞越高速公路收费站；
点火太晚会撞站，推力过猛会飞过头冲出马路。

【硬性约束】
- 单 index.html + 原生 JS 单 IIFE，本地 vendor 一份 three.js，不连任何 CDN，
  双击 index.html（file:// 协议）必须能离线跑
- 车模按特斯拉官网参考图还原，但车高/车长/车宽是游戏设定，不是真实参数，
  并在页面和 README 写明这是概念娱乐作品

【建模方法——严格按顺序，不许跳步】
1. 先把参考图按视角切片：正前、正后、正侧、前 45、后 45、俯视、细节特写
2. 每个视角做「带网格的裁剪放大」，目视读数，量出关键比例
   （车高/车长、尾板宽/车尾宽、灯条厚宽比、排气口数量与排布、轮径/车高）
3. 只用参数表 + 最少面片搭轮廓，渲染成正交视角，和参考图叠加对比，
   轮廓不重合不许进下一步
4. 轮廓过关后按控制点重新定参数，再逐区加细节（前脸、尾灯、扩散器、轮毂）
5. 正后视图只用来判断尾部层次与部件顺序，不要用它推三维尺寸
6. 每轮把对比图保留下来，命名带编号

【可验收标准——每条都可证伪】
- 车身包围盒 4.72 × 2.05 × 1.13 m，实测偏差 ≤ 1.5%
- 正视图宽高比 ≈ 1.53（按车高 1.13 反推车宽 ≈ 1.73）
- 尾部层次自上而下只能是：贯穿式尾灯条 → 银色尾板面 → 深色面板 → 碳黑扩散器，
  且灯条与尾板同宽
- 排气口是车尾中部一排 4 个，不是 2×2
- 车轮 O/D 与实测值的差 ≤ 3%，静止时轮胎最低点贴地（y 误差 < 1e-6 m）
- 12 个推进器按真实布局：车底 4 个向下、车尾 2×2 向后、车身两侧成对做姿态控制

【玩法设计】
- 冷气定量不补：总装填 100%，满罐只有 5 秒总点火时间，够约 7 次点火

- HUD 冷气 + 高度双仪表，含危险区/安全区
- 难度要分档：粗放飞行永远 7 站结束；精确控制能突破，
  靠「穿站高度越低 → 冷气返还越多」把资源上限变成技术上限
- 收费站间距随机化，并周期性出现「连站」，不能背节奏
```

三条最关键的改写逻辑：

1. **把流程写进提示词**。「先量比例 → 搭轮廓 → 叠加对比 → 轮廓重合才许加细节」这四步是踩过坑才总结出来的 —— 原来没定顺序，模型是在壳建完之后才发现尾板宽度错了。
2. **每条标准都要可证伪**。「不像」换成「宽高比 1.53」「灯条与尾板同宽」，AI 自己就能判断过没过。
3. **验证工具是交付物不是附属**。有了离线的校验 + 渲染脚本，改 geometry 才能靠逐像素比对确认无损，而不是每次肉眼看图。

## 功能亮点

- **冷气限量、烧完不补**：一罐氮气只有 5 秒总点火时间（每秒耗 20%），整局不回充。罐子见底推进器点不着，车只会下坠，最终必然撞上下一座收费站 —— 不可能无限飞。低量时仪表琥珀色闪烁 + 提示音，烧干时有阀门关闭声与「冷气耗尽」结算文案。
- **按真实冷气推进器原理做视觉**：不燃烧、无火焰。高压气体喷出后骤冷，空气中水汽凝结成白雾羽流；10 个喷嘴按真实布局（车底 4 个向下喷抬起车身、车尾 2×2 圆形簇向后推、车身两侧成对做姿态控制），羽流为扩张形而非锥形收尖，含霜圈与地面铺散效果。
- **一比一还原的车模**：按 tesla.cn 官方渲染图逐列实测（Sobel 边缘检测 + 385.5 px/m 标定）反推车身型面：长 4.721 m / 宽 2.051 m / 高 1.130 m（官方 4.70 / 2.06 / 1.13）。长鼻薄楔、机盖一条长斜面直接爬进风挡、车顶峰值在中轴偏前、行李厢面滑下后一道垂直尾板切面。折面（facet）几何按面片拆分顶点，横向是锐利棱线、纵向保持顺滑 sweep，还原「隐形战机」式的大平面折板语言。
- **本地排行榜**：localStorage 保存最多 10 条记录，按得分降序（同分比站数、再比时间），前三名奖牌配色，本次成绩高亮，刷新不丢。
- **完整的失败判定**：点火太晚撞收费站（前缘进入/后缘穿出两段检测 + 最低高度采样，避免高速穿模）；飞过 CLEAR_ALT 8.6 m 算通过；超过 MAX_ALT 34 m 判「飞过头冲出马路」。
- **WebAudio 程序合成音效**：EV 电机为 sine/triangle 低鸣 + 高频逆变器啸叫；冷气推进器为高通 1250 Hz + 带通 4600 Hz 的气流嘶声，阀门开启瞬间叠加泄气爆破音。
- 路面蓝色光带提示最佳点火位置（按数值积分实时算出到达 CLEAR_ALT 所需时间 × 当前车速）；HUD 双仪表（冷气 / 高度，含危险区与安全区）；每过一站提速 2.4，上限 84。
- **分享与移动端**：带 OG / Twitter 卡片（1200×630 实机封面），链接分享到社交平台有标题、描述与缩略图；小屏下开始卡片与底部 HUD 自动让开左下角的 GitHub 悬浮入口，两个仪表标签也不再互相挤压。

## 技术栈

Three.js r149 精简构建（本地 `libs/three-r149.min.js`，446 KB / gzip 115 KB，见下节）+ 原生 JavaScript 单 IIFE，无构建步骤、无外部依赖、无 CDN，双击 `index.html` 即可离线运行（`file://` 协议实测通过）。

关键实现：

- **截面放样建模**：8 控制点横截面 + Catmull-Rom 平滑（`sectionOutline`）/ 折面模式（`facet`，控制点直接当顶点、段间直线相连）→ 沿 z 放样（`loftGeometry`）→ 端面扇形封口。轮拱不靠布尔：逐截面把底高抬到 `yc + sqrt(R² − d²)`，方角轮眉（中间平顶、两端圆弧）。
- **顶点拆分做硬棱线**：`loftGeometry` 的 `split` 模式按面片复制顶点 —— 面片间不共享顶点 → 棱线法线不被平均（硬边）；同面片沿 z 共享顶点 → 沿车长方向仍平滑。直接用 `flatShading` 会把车长方向的顺滑型面打碎成一圈圈等高线，不可取。
- **车壳贴面工具**：`surfaceTopY` / `surfaceSideX` 按参数表插值，把大灯刀锋透镜（`lensWedge`）、DRL 灯丝（`topRibbon`）、进气口、侧鳃、车门分缝精确压到曲面上，不会像方块那样支出来。
- **r149 色彩管理手动补**：r149 默认 `ColorManagement.enabled = false` 而渲染器输出 sRGB，需把材质 `color`/`emissive` 与雾色统一 `convertSRGBToLinear()`；金属漆必须配环境反射（6 张 canvas 渐变 → CubeTexture → `PMREMGenerator` 预滤波赋给 `scene.environment`），否则金属材质渲染成纯黑。
- **羽流 shader**：`along = 1 - vUv.y`（喷口在几何体底端）+ fresnel 边缘增强；白雾用 NormalBlending（遮挡而非发光），不做颜色 alpha 预乘。
- **物理双时钟**：物理用封顶 0.05 s 的 `dt`，结算动画用 `dtReal`，低帧率下结算不会拖成慢动作。
- 粒子 `gl_PointSize` 是像素单位，需按世界尺寸给值并在 shader 里 clamp。

### three.js 精简包

`libs/three-r149.min.js` 不是官方完整构建，而是用 esbuild 从 `three@0.149.0` 按需打包的精简版：只导出游戏与离线工具实际引用的 47 个符号（完整构建导出 407 个）。608 KB → 446 KB，gzip 153 KB → 115 KB；同一场景下与完整构建相比，三通道均值差 < 0.1/255。

符号列表**必须扫描生成，不要手写** —— 漏一个符号不会报错，而是静默降级。第一次打包漏了 `sRGBEncoding`，`renderer.outputEncoding` 变成 `undefined`，整场画面偏亮发灰。

```bash
npm i -D three@0.149.0 esbuild
# 1. 扫描所有 T.Xxx 引用（游戏 + 离线工具）
grep -ohE '\bT\.[A-Za-z_][A-Za-z0-9_]*' game.js roadster-model.js tools/*.cjs \
  | sed 's/^T\.//' | sort -u        # 生成 import/export 同一份列表 → entry.js
# 2. 打包：IIFE + 全局 THREE，并补 CommonJS 导出供 Node 工具 require
npx esbuild entry.js --bundle --format=iife --global-name=THREE --minify \
  --target=es2018 --outfile=libs/three-r149.min.js \
  --footer:js="if(typeof module!=='undefined'&&module.exports){module.exports=THREE;}"
```

改动 `game.js` / `roadster-model.js` 后若引入了新的 `T.Xxx`，需重新扫描并重建，否则运行时才暴露。

### 合批降 draw call

车身原本 235 个独立 Mesh（每个一次 draw call）。`roadster-model.js` 末尾的 `mergeRigidGroup()` 在模型构建完成后，按材质把**刚性组内**的不透明网格合并成单个 BufferGeometry：车体一组，4 个轮子、12 个推进器各自一组（组本身的滚动 / 摆动变换不受影响）。

- 合并前先把每个网格的局部矩阵 `applyMatrix4` 烘进几何体，因此视觉无损：离线渲染 6 个视角逐像素比对，60 万像素里最多 4 个像素不同（三角边缘浮点取整）；
- 保留 `full-width-red-tail-lamp` / `license-plate` / `diffuser-roof` / `stowed-active-spoiler` 四个地标网格不合并，供 `check-model` 校验尾部层次；
- 透明材质（羽流）、`InstancedMesh` 一律跳过；
- 实测：模型 Mesh 235 → 87，全场景 draw call 373 → 221，三角面数不变，帧率不变。

## 运行方式

任意现代浏览器（需 WebGL）：

- 直接双击 `index.html`（完全离线可用），或
- 在本目录起一个静态服务：`python -m http.server 8080`，访问 `http://localhost:8080`。

操作：长按 `空格` / 鼠标左键 / 触屏按住 = 点火；`R` 快速重开。点击「开始起飞」进入游戏。

  - 排行榜：空榜提示 / 降序排序 / 同分紧邻 / 本次高亮 / 刷新持久化 / 超 10 条截断 / 低分被挤出，全部通过；
  - 尺寸实测：车身包围盒 4.721 × 2.051 × 1.130 m，与官方渲染图标定（385.5 px/m）逐列比对；
  - 合批无损性：离线渲染 6 个视角逐像素比对，60 万像素里最多 4 个像素不同（三角边缘浮点取整），三角面数 49972 保持不变；
  - three.js 精简包：与完整构建同场景对比，三通道均值差 < 0.1/255、亮度直方图最大偏差 0.12%；
  - 全部用例零 pageerror、零 console error，`file://` 直开正常。
- **边界说明**：车辆造型按公开渲染图 1:1 对齐，但推进器物理、冷气消耗速率、赛道参数均为娱乐化演示设定；音效为程序合成，非实车录音；排行榜仅存本机浏览器 localStorage，不同浏览器/设备不互通。
